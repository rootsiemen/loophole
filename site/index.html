Find the security holes in your code — before someone else does.

Loophole is a static security scanner that ships as one Python file with zero dependencies. Point it at a codebase and it finds hardcoded secrets, injection flaws, XSS and more — then tells you why each one matters and how to fix it.

Up and running in one command

Clone it, run it. Machine-readable output for pipelines, human output for people, and --fix-dry prints mechanical fix suggestions as diffs — it never touches your files uninvited.

  terminal
# clone — that's the entire install
git clone https://github.com/rootsiemen/loophole
cd loophole

# scan a project
python3 loophole.py scan ./your-project

# only criticals and highs, specific folder
python3 loophole.py scan ./src \
  --severity critical,high

# preview fixes as diffs (dry run)
python3 loophole.py scan . --fix-dry
  pipeline output
# JSON for your own tooling
python3 loophole.py scan . --json

# SARIF 2.1.0 for code scanning UIs
python3 loophole.py scan . --sarif

# exit code 1 on critical/high findings,
# so CI fails the build exactly when it should
python3 loophole.py scan . ; echo $?

First-class in GitHub Actions

The official Action runs Loophole on every push and pull request and uploads SARIF results to your repository's Security tab — findings show up where your team already reviews code.

  .github/workflows/security.yml
name: Security scan
on: [push, pull_request]
permissions:
  security-events: write
jobs:
  loophole:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: rootsiemen/loophole@v1
InputWhat it does
pathDirectory to scan (default: repo root)
severityMinimum severity to report
upload-sarifPublish results to code scanning
fail-on-findingsFail the workflow on critical/high

Open source, built in the open

Loophole is MIT-licensed and maintained in public. A new rule is one focused function plus fixtures — the codebase is a single readable file, so your first contribution is an afternoon, not a week.
