What it catches

Thirty-five rule classes across the bugs that actually ship to production — each finding explains why it is dangerous and how to fix it.

Hardcoded secrets

API keys, passwords, tokens and private keys committed straight into source files.

Injection

SQL injection, command injection, XSS and unsafe deserialization sinks.

Taint tracking

User input is followed from source to sink, so findings are real flows, not just keyword matches.

Weak crypto

Broken hashes, ECB mode, insecure randomness and disabled TLS verification.

Traversal & SSRF

Path traversal, server-side request forgery and unsafe file handling.

Web misconfigurations

Debug mode left on, permissive CORS, missing security headers and more.

Run it in seconds

No install, no platform, no account. If Python 3 runs, Loophole runs.

# clone and scan — that's it
git clone https://github.com/rootsiemen/loophole
python3 loophole.py scan ./your-project

CRITICAL Hardcoded AWS secret key — config.js:4
HIGH     SQL injection (tainted input reaches query) — db.py:31
         fix: use parameterized queries / prepared statements

GitHub Action

Run Loophole in CI and publish results straight to your repository's Security tab via SARIF.

name: Security scan
on: [push, pull_request]
permissions:
  security-events: write
jobs:
  loophole:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: rootsiemen/loophole@v1

Contribute

Loophole is maintained in the open and built to be extended: a new rule is one focused function plus tests. Good first issues are labelled, pull requests get reviewed quickly, and the scanner dogfoods itself — it scans its own codebase clean.

1. Pick an issue

Start with a good first issue or propose a new rule.

2. Read the guide

CONTRIBUTING.md covers setup, tests and rule anatomy.

3. Open a PR

Small, focused pull requests with tests — feedback comes the same day.
